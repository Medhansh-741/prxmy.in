# Prxmy portfolio

## Structure

The portfolio follows a direct reading order: introduction → projects → open source → tech stack → about/experience → contact. Navigation uses these same names. Section headings name their contents; body copy describes the actual work. No eyebrow slogans, handwritten annotations, tilted text, decorative stickers, or oversized editorial catchphrases.

The default body size is 16px. Supporting descriptions are 14–15px, and small technical metadata is 11–13px. The font system uses only Geist and Geist Mono.

## Hardware with a purpose

- The motherboard is an optional visual navigation. Its CPU opens the résumé, memory opens the tech stack, drives open projects, GPU opens open source, and the Tux mascot leads to contact. The standard navigation provides the same destinations.
- Project cards use compact server-module frames. Two featured projects lead with a real cover/illustration, readable descriptions, technology lists, source links, and expandable engineering details. Other projects use compact rows. Filters switch between all work, tools/systems, and civic technology.
- The original three-fan GPU from Prakhar’s GitHub profile selects OWASP, Sugar Labs, or EcoAudit contribution evidence. Its hub counts are verified against GitHub’s public API and carry their own check date. Fans turn only while visitors interact with the component; reduced motion disables this.
- RAM modules visually group backend/data, web, and infrastructure skills. They do not pretend to be live system readings.
- The contribution fan calendar uses the existing verified snapshot with its original check date and supports keyboard exploration.

## References and specific lessons

- [Prakhar’s GitHub](https://github.com/prx-my): actual CPU/GPU artwork, tactile electronics, cream/cobalt colours, Tux, and contribution fans. Asset sources and notices are recorded in `public/hardware/ASSETS.md`.
- [Browser Use on BestSaaSWebDesigns](https://bestsaaswebdesigns.com/site/browser-use): inspected its full desktop/mobile capture and hierarchy. Borrowed straightforward navigation, bordered product surfaces, clear actions, and Geist typography.
- [LocalCan on Godly](https://godly.design/website/localcan/) and [the live site](https://www.localcan.com/): inspected its bounded feature demonstrations and selector controls. Borrowed explicit component boundaries and controls that reveal useful evidence in place.
- [Stylogeny’s Risograph reference](https://stylogeny.com/styles/risograph-indie/): limited spot colours and tactile graphic surfaces, confined mostly to the hardware artwork. Text and the page background stay clean.
- [Awwwards portfolio gallery](https://www.awwwards.com/websites/portfolio/): reference for a recognisable personal identity and project-led browsing. Ordinary scrolling and navigation stay intact.

These sources inform the layout and interactions. The only imported visual assets are the portfolio owner’s existing approved GitHub artwork and the MIT-licensed Devicon Linux mascot. No reference-site screenshots are reused as portfolio artwork.
